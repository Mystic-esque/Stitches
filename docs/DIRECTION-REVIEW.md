## Why this revision

The September gallery did not meet its own “structurally distinct” rule: three top drawings share the same body/sleeves and three skirt drawings share the same shape, largely changing color and length. Its garment mode also hides technical cutting details that the previous workbench made visible. The screenshot's fold arrows, cut counts, coral edge deltas, sleeve consequence and original/proposed comparison are the more useful design seeds. They were illustrative and lacked allowances, notches, full-size scale and a complete reviewed sleeve relation; those must be developed and qualified, not treated as already solved.

The research's strongest contribution is continuity with the physical project. The agent needs the maker's confirmed pattern source, fabric, equipment, progress and observations to choose a relevant next action. The “I'm stuck” entry is a high-value moment because it can start from the actual step and ask a discriminating question. Sanity can author the relationships that make that possible.

Two parts of the research need boundaries. A single inspiration image cannot reveal hidden pieces, correct measurements, fabric properties or an exact construction sequence. A trouble photo can suggest visible observations but cannot certify a fit diagnosis or a machine/needle prescription. Numeric examples in the attachment are illustrative; only source-backed, material-compatible, tested guidance can become an instruction.

## Recommended synthesis for implementation

**Stitches is a project-aware sewing companion with a precise pattern workbench.** The primary loop is **Inspire → Plan → Prepare → Make → Check → Resolve → Continue**. The pattern workbench teaches construction and supports exact changes where a qualified pattern artifact exists. The agent coordinates the loop using scoped, validated tools and keeps a durable record. The user can always inspect the source and decide whether to adopt a change.

The full first application must include two genuinely different source-qualified example projects, a broader planning path for a person's own project/reference, reusable private measurement/material/equipment profiles, a connected cutting/assembly view, step-focused Make Mode, contextual troubleshooting including an optional close-up photo, and a live Sanity/Context/Gemini demonstration. Stronger CAD, unrestricted photo-derived patterns, cloth physics and automated fit certification are later research, not release claims.

Capability states are visible per project: **Plan only** (components/techniques and open questions), **Guided making** (source-bound procedures and confirmed project steps), **Pattern mapped** (exact piece/cut relationships), **Cut checked** (geometry/layout/print checks), and **Maker reviewed** (physical evidence for that specific design). A person can still use planning and teaching when exact pattern geometry is unavailable.

## Second pass through the supplied research

The research is strongest where it explains a *working garment model*, not image-to-pattern magic. Adopt: (1) reference image to **editable visible features and unknowns**, with each confirmed feature linked to a Sanity component/technique; (2) a missing-input view that asks only for the next needed measurement, material or tool fact and visually explains how a measurement is taken; (3) reusable private measurement and fabric/equipment profiles so the next project starts smarter; (4) an authored step plan with dependencies, checkpoints and project history; (5) “I'm stuck” beginning with the live step and a discriminating test, including optional photo observations the maker confirms. The same project should remember unsuccessful attempted fixes so the agent does not repeat them.

The research also suggests a future Fit Check, material-stash planning and an evolving garment-making operating system. Keep the state model extensible for these, but an automatic front/side/back fit score would overclaim present visual and physical evidence. Start with maker-described fit observations and safe source-backed hypotheses. Its example needle sizes and dart distance are illustrations, **not** qualified values to seed as advice. Likewise a picture may suggest a square neckline or puff sleeve but cannot disclose a hidden zipper, exact pieces or difficulty as fact. The product should reward uncertainty with a better next question, not a confident invented answer.

The older workbench is therefore a proof of *information worth showing*, not a screen to clone. A better layout may put one technical piece beside the active physical step, or open a focused mobile sheet; what matters is whether a maker can understand cut/fold/grain, joins, change consequences and recovery.

## Parametric-pattern research follow-up

The owner's later SVG/engine research sharpens the technical target without changing the project-aware product loop. Accept its central premise: a measured, semantic pattern artifact must generate the technical view; SVG paths alone are not the pattern, and no model may rewrite them as a shortcut. FreeSewing is the first engine candidate to test against one actual licensed design, not proof that every garment or marking is available. SeamScape's inspect → preview → confirmed apply/save flow is a useful safety model, but its advertised full API access is Enterprise and is not a $0 dependency. Seamly2D/PatternSoft are terminology and workflow references. `PATTERN-ENGINE-DECISION.md` records the explicit artifact, command, adapter and qualification gate. The older shoulder illustration remains illustrative until this passes.
