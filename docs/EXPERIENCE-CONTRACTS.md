# Companion 2.0 — screen and state contracts

Read PRODUCT.md, DESIGN.md and ../devpost/prd.md together. These are target user experiences, not implemented test results.

## First visit
1. Landing explains how a garment reference relates to flat pieces and making steps; no signup.
2. Maker chooses a genuinely different supported example or “my idea/pattern.” A mere recolor is not a separate example.
3. Detail shows real source, garment/method/material demands, what Stitches can check and what remains human/unsupported.
4. Starting creates a guest project and routes to its next eligible action. Restart/reopen resumes it. No prewritten AI conversation is presented as live agent work.

## Pattern literacy moment
From a garment region, select the sleeve. The flat sleeve piece gains focus, with cut count, mirrored orientation, grain, marks, seam/cut lines and joining edge (only where source-qualified). Select the edge to find the armhole partner and assembly step. “Why curved?” opens a source-backed explanation. If the exact edge binding is missing, the app says so; it can still teach a general concept but cannot highlight a purported exact edge.

## Change moment
Maker asks to lengthen a supported garment while keeping neckline. Server verifies operation/version/bounds and locks, drafts complete affected pieces and recomputes cut plan/steps. Original dashed and proposed solid outlines show actual changed geometry, units and all affected parts. Review includes unresolved checks; only deliberate Keep makes a new immutable version. Unsupported alteration yields explanation and available alternatives, not a plausible-looking fake.

## Preparation moment
Maker enters body measures, fabric dimensions/direction and equipment. Stitches separates known measures, unknowns, compatible methods and missing pattern evidence. A qualified cutting layout shows fold, selvage, grain, cut count and scale. Bounded search failure is reported as “not found under these assumptions,” not proof of impossibility. A planning-only project remains helpful but cannot export cutting pages.

## Make and stuck moment
Maker opens a step requiring a sleeve-to-armhole join. It shows the actual pieces, sides, notches, authored allowance and a check before sewing. “I'm stuck” inherits the project and step; the maker records what does not line up. Stitches asks a discriminating check and shows relevant markings, then narrows source-backed possibilities. If the pattern binding or fabric behavior is unknown, it asks for that fact or offers a safe general check. It does not prescribe unverified clipping, recutting or numeric alteration. The maker marks a remedy attempted and later confirmed or unsuccessful; that state affects the next suggestion and survives resume.

## Photo and fit uncertainty
A reference photo identifies visible style features only, with editable confirmation. A close-up troubleshooting photo returns observations that the maker can reject. “Fit check” means structured self-observations and qualified hypotheses, not a simulated body fit or automatic change. Photos are private/temporary, with visible deletion and a no-photo route. Quota/offline gives manual feature and symptom entry.

## Content correction
An editor fixes a source-backed method shared by two different project examples in development. Exact graph fingerprints identify affected future steps, pending proposals become stale as appropriate, and each project's UI asks for review. Historical completed steps remain. The KB is separately rebuilt/reviewed and its actual served response verified. A stale KB is displayed as unavailable/conflicting, never silently merged into authoritative instructions.

## Failure and recovery
Guest data reloads after local restart; duplicate Keep is one revision; stale tab gets review of changed basis. Missing Sanity source cannot be replaced by a fixture in live mode. Gemini 429/cancel/timeout preserves an explicit run checkpoint and useful manual path. A rejected pattern/cutting check never becomes “ready” after a nicer rendering. Knowledge, tool and physical evidence states remain separately visible.

## Mobile and accessibility
On phone the maker moves among one focused garment/pattern/step view with bottom navigation and a dismissible help sheet. Technical marks remain zoomable and readable. Keyboard user can select piece, inspect partner, open explanation, run a diagnostic and return focus to the originating step. Motion conveys nothing essential; reduced-motion retains all facts.
