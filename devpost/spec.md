This is a target contract. The current illustrative runtime and proofs are listed in docs/STATUS.md, not silently promoted to this spec. Use installed library and official provider documentation for API details before code changes. No invented Sanity endpoint or model capability.

## C01 — Trust and ownership
- Shared, source-reviewed instructional content is authored in Stitches Sanity project `l4eeamth`, dataset `development`. Exact Content Lake reads and actual KB-only Context MCP reads are separate typed server adapters. No user-uploaded images, measurements or private projects go to Sanity.
- Guest projects/profiles/runs/artifacts use a durable local transactional repository keyed to an opaque HttpOnly session cookie. Scope every query and mutation; do not expose shared demo state. Browser holds only UI/draft state. Secret tokens stay server-only.
- A guest project copies a profile into a named semantic basis. Kept versions are immutable. `basisHash` includes source/version, measurements, material, equipment, options, method IDs and relevant content fingerprints. The UI must show what changed when a basis becomes stale.
- Initial local profile slice: one named profile per guest, optional mm/degrees notes, experience and equipment; immutable profile revisions with canonical hashes. Copy requires both saved profile and project sequence/hash and records `profileBasis` in a new project revision. Fill only missing values (zero is present), union exact tool names, retain conflicts and show the preview. No inferred measurement aliases. Ordinary plan create/edit cannot forge/change copy provenance. Backup import retains historical provenance without profile access; restoring a maker backup requires explicit review and saves a new profile revision. No profile fabric-stash, step progress, account sync or deletion capability is implied by this slice.
- Provider input is minimized and consent-aware. Close-up/reference uploads are validated, re-encoded, temporary, deletable and absent from normal logs; never sent to Sanity.

## C02 — Public knowledge graph
Retain existing `sourceDocument`, `pattern`, `patternVersion`, `patternPiece`, `seamConnection`, `adjustmentRule`, `instructionStep`, `fabricRequirement`. Extend with versioned `garmentComponent`, `sewingTechnique`, `equipmentClass`, `fabricClass`, `constructionProcedure`, `issuePattern`, `diagnosticTest` and `remedy` records. Procedure maps to steps, pieces, seams, techniques and prerequisites. Issue maps to component/step/material/tool context; tests discriminate hypotheses and remedies carry conditions/risks. All claims identify reviewed sources, rights and applicability. A schema declaration alone is not deployed or proof of valid content.

An exact resolver rejects dangling/cross-version references, cycles, invalid condition IDs, unsupported adapter IDs, contradictory numeric envelopes and methods without applicability evidence. Distinct project templates point to qualified complete source/version; color variants are options within one template. KB excerpts explain; exact graph decides eligibility, sequencing and binding. An unverified or stale KB response is not silently treated as an exact rule.

## C03 — Capability and provenance
Represent capability as a checked, monotonic claim set with provenance, not a UI adjective: `plan_only`, `guided_making`, `pattern_mapped`, `cut_checked`, `maker_reviewed`. Moving up requires explicit receipts. A pattern-mapped receipt binds actual piece and named edge IDs, grain/fold/count/notch and source/version. A cut-checked receipt binds exact geometry and independent layout/print checks. A maker-reviewed receipt includes exact scope and consented physical evidence. A photo or attractive 3D mesh cannot promote capability.

User-owned or third-party patterns are only referenced/mapped where rights allow. No redistribution of externally authored pages without a recorded grant. Always distinguish body measurement, garment finished measurement and ease; do not invent numeric allowances, yardage or fit predictions.

## C04 — Project state machine
`idea → plan → preparation → making → checkpoint → issue → resolved/paused → continued → completed` is a navigational journey, not a single linear status. A project can revisit plan after a variation or correction. Every operation has `projectId`, `expectedSequence`, `basisHash`, `idempotencyKey` and an authenticated guest scope. Drafts/proposals do not mutate kept versions. Keep/progress/resolution are transactional; stale and duplicate events have deterministic responses. Progress belongs to revision + step/method fingerprints, so editorial updates request review of future steps without erasing historical work.

Store explicit symptom, observation, test, result, hypothesis, proposed remedy, maker confirmation and outcome separately. Never mark a remedy confirmed because Gemini said it is likely. A physical action with irreversible risk requires a clear check/confirmation.

## C05 — Pattern-connected workbench
Implemented restricted study: `PatternBoard` renders actual server-generated Sandy 4.10.2 straight-band geometry from four saved, exact body-note keys. Numeric paths are schema-validated; stable piece/edge/mark selection shows engine count/fold/grain, unresolved mark counterparts and pending source-linked local study steps. A strict length-study command performs two complete redrafts, compares original/after measured edges and preserves waist/band geometry. This remains `plan_only`, cannot be kept/exported as a cutting template and does not substitute a local DAG for Sanity-authored making instructions. Complete qualified mapping, garment-region connection, methods, rights and physical gates below remain open.

The main 2D view uses one canonical versioned mapping from finished garment region to pattern piece/edge to seam connection to instruction step. Source-qualified layers show cutting line, stitch line, allowance, fold, grain, mirror/count, notches and right/wrong side. Any missing source layer is marked absent; illustrative SVGs cannot become cut-ready output. Selected alteration renders original and proposed outlines with units and highlights affected edges, related pieces, joins, cutting and steps. Geometry/layout validators are independent of rendered SVG and model narration. An optional 3D scene can consume the same IDs but cannot replace technical 2D or imply drape/fit.

The source of truth is semantic pattern definition + confirmed private inputs + registered operation, **not SVG markup**. A deterministic adapter emits an immutable `PatternArtifact` with engine/version/input hash, physical units, stable piece/edge/notch IDs, measured stitch/cut outlines, fold/grain/count/allowance metadata and validator diagnostics. The viewer derives SVG/interactive vector elements and click targets from it; client-selected IDs are re-resolved server-side. FreeSewing is the first qualified adapter spike, not an already selected or proven engine. See `../docs/PATTERN-ENGINE-DECISION.md` for the engine and rights gate.

## C06 — Preparation, variation and outputs
- Initial registered research command `study_hem_length` accepts baseline ratio 0.1–1, delta ±200 mm and engine allowance 0–30 mm, then checks the resulting ratio again. These are mathematical research bounds, not an approved fit/alteration envelope. Missing measurements, unsupported source/cut/fold contracts and changed saved bases fail without defaults or project mutation. The new production study does not close qualified variation → keep → resume, layout or export gates.
- Private body notes use separate length and angle maps: UI centimetres convert to stored millimetres; shoulder slope remains degrees. Match only recognized exact source-listed measurement labels and disclose unknowns. Preserve unexposed and legacy notes when the brief/source view changes; no implicit hip/hips or bust/chest substitution. An optional angle map must not add default fields to unchanged historical plans. All values bind the immutable project basis; storage bounds or complete field counts are not a qualified engine measurement envelope, finished dimensions, ease or fit check.
A registered operation has typed args, reviewed bounds, allowed locks, prerequisites, conflict rules, affected IDs and a deterministic adapter. It re-drafts complete eligible pieces from base inputs; validates joins, intended ease/tolerance, notches, allowances, counts and option compatibility; recomputes step DAG and layout. `feasible`, `proven_impossible`, `search_not_found`, `missing_input` and `unsupported` are distinct.
Raw SVG-path rewriting and unconstrained point movement are not agent tools. A named operation such as a supported hem-length change must preview a fully regenerated artifact, show before/after consequences, then require an explicit keep. Repeat drafts at two materially different inputs to test grading/option behavior and stable bindings; a visually plausible vector alone is not a result.
A project plan and tailor-friendly summary can be exported with limitations. Full-size/tiled vector pattern export requires rights, complete geometry, calibration, page joins, cutting marks, revision manifest, deterministic independent checks and the physical review gate for its precise supported envelope. A blocked cut-ready export may still provide a non-cuttable review package.

## C07 — Make and diagnostic engine

Implemented initial boundary: immutable guest-owned scrap events (observation, comparison start, user-reported result, pause), project sequence/hash plus exact catalog/diagnostic fingerprints and source/test/remedy IDs, and optimistic history sequence. New advice-dependent writes require current applicable exact sources; exact acknowledged retries and private pause facts do not require a fresh network read. Imported v3 history stays explicitly untrusted and cannot authorize an attempt. Failed/uncertain sample comparisons stop rather than loop. This is pending-review sample education, not a qualified step, confirmed cause or actual-garment fix; the complete authored step contract below remains a release requirement.
Resolve the authored prerequisite DAG for the kept revision; filter conditions, compatible method and equipment, then expose the next eligible operation. Each step binds diagrams, pieces, edge IDs, orientation, source-authored numerical details, checkpoint and educational explanation. A content correction fingerprints affected steps and creates a review state.
An “I'm stuck” event starts from the active step plus project context. The deterministic engine retrieves applicable issue hypotheses, asks the highest-value available diagnostic test, stores the result, narrows hypotheses and presents supported remedies with risk. Unknown/conflicting evidence yields uncertainty and a safe stop. Optional photo analysis returns observations only; user must confirm before a test outcome is accepted. No automatic body-fit grade, hidden seam inference or irreversible fix.

## C08 — Bounded Gemini agent
Implemented initial preparation slice: `inspect_project` includes deterministic preparation checks; `inspect_preparation` is a read-only helper; `resolve_exact_graph` and `retrieve_context` accept empty arguments only. Provider-native stage controls allow the eligible read, then prohibit tools for the explanation; independent server validation still refuses parallel/repeated/out-of-order calls. Three mandatory reads plus explanation fit four attempted requests. Bind saved project sequence/hash, applicable catalog/diagnostic fingerprints and full history head/hash; revalidate around operations and compare actual served KB text hash at final acceptance. Private body values/prose/photos are withheld. Per-run consent, private signed history, transactional reservation/checkpoint, 120-active-second/four-attempt bounds and conservative daily free authorization are implemented. Only acknowledged response reads can be retried without inference; unknown provider outcomes cannot resume. Actual Sandy/Tina provider proofs pass (Tina recovery uses a clearly labeled injected local transport interruption). Model output is unverified planning insight and cannot mutate/certify a project; complete making/drafting tools below remain release work.
Extend the existing verified provider adapter into one planning/execution loop with registered tools: inspect_project, resolve_exact_graph, retrieve_context, check_prerequisites, check_pattern_mapping, check_fabric, get_diagnostic_tests, record_observation, draft_supported_change, inspect_proposal and prepare_next_step. These are application contracts, not asserted vendor API names. The server validates every tool call and stage precondition; Gemini cannot issue arbitrary shell/GROQ, bypass readiness, write to Sanity or keep a revision.
Default cap: at most 4 model requests, 10 tool calls, 3 alternative drafts and 120 seconds active time per run, subject to free-tier/quota checks before each request. Persist checkpoints and idempotency so cancel/timeout/429 can resume or fall back manually without duplicate artifacts. Explanations cite exact receipt/source IDs and label KB freshness/conflicts. The UI never shows a scripted assistant transcript as a real response.

## C09 — Server API and boundaries
Implemented pattern study transport: `POST /api/projects/:id/pattern-study` requires same-origin JSON, private owner, strict 4 KiB-bounded input and saved sequence/hash/source fingerprint before drafting. Recheck actual source/project afterward. Safe errors include code/message/retryable/request ID and owned current basis on stale input. Only numeric study geometry/metadata is returned, with `projectChanged=false` and `cutReady=false`; no inference/write/keep occurs. Exact catalog reads are abort-bounded at 12 seconds with zero SDK retries; browser reads are bounded at 15 seconds and preserve manual fallback. Full proposal/progress/physical boundaries below remain open.

Implemented W08 continuation transport (initial read-only envelope verified): `GET/POST /api/projects/:id/agent` reads privacy preview/history or starts a consented run without inference; `GET/POST /api/projects/:id/agent/:runId` reads state or explicitly advances/resumes/cancels. Strict task/basis/consent bodies, same-origin mutation checks, owner resolution before network and no provider transcript in responses. Per-run private signed history and request reservations are persisted transactionally. Unknown provider outcomes cannot resume; acknowledged source reads can recover without another model request. Daily limits count attempts, not only successful outputs. Deterministic/API/five-width browser and separate actual two-source Gemini/Context receipts are recorded in STATUS. Full C09 currentBasis error envelopes and later geometry, proposal/keep or physical-progress tools remain unimplemented; this slice does not close the full contract.
Use small same-origin typed endpoints for catalog, guest profile/project CRUD, plan/preparation, proposal/keep, step/progress, issue/test/remedy, optional photo analysis, agent runs and authorized artifacts. Validate body/IDs/units/bounds with strict schemas and explicit capability checks. Use an error envelope with code, message, retryable flag, request ID and current basis when stale. Distinguish invalid input, guest denial, stale basis, unsupported check, quota, unavailable source and provider outage. Long work returns a run ID and can be cancelled; no speculative external API names in routes.

## C10 — Verification
- Domain: graph cycles/dangling refs/cross-version/condition mismatch; piece/edge/fold/count/allowance mapping; variation dependency closure; layout states; instruction DAG; diagnostic discrimination and uncertainty.
- Integration: real development Sanity exact vs served KB, source correction across two different projects, stale evidence, guest isolation, transactional keep, provider quota/cancel/resume and temporary photo cleanup. Fixtures are explicitly labeled.
- Evaluation: freeze tasks and expected source applicability before runs; compare keyword-only over the same corpus with graph+Context/tools on next-step, diagnostic choice, dependencies, refusal and completed maker task. Separate retrieval metrics from end-to-end outcomes and record latency/calls/cost.
- Browser/maker: actual desktop/mobile/keyboard/reduced-motion screenshots and user journeys; print calibration and physical make per cut-ready scope; report failures. A reference HTML screenshot is design evidence only.
